# v1.6.0 · 行囊图标化 · 八页签主菜单 · 匠材打造

> 2026-10-24　·　主题：把「读数字」改成「看东西」，把「八个浮层」收成一个菜单

## 一句话

行囊后三栏从文字列表变成**一格一物的图标 + 数量角标**；八个各开各的浮层收成**一个带页签的主菜单**；装备链补上入口——怪物与 Boss 掉**九种匠材**，可把**白装 / 蓝装当胚**重铸成更高品质。

## 一、行囊四栏图标化

- **材料栏常驻 13 格**：四阶玄晶（凡 / 灵 / 玄 / 神）+ 九种匠材（玄铁锭、妖兽皮、妖骨、灵蚕丝、赤炎砂、寒玉髓、玄鳞、陨星铁、妖丹）。不持有的也留格、图标灰显，缺什么料一眼可见；持有什么符文就追加哪些符文格。
- **丹药栏 3 格**（红药 / 蓝药 / 传送符），点一格即服用，战斗中亦可。
- **任务物品栏**按已完成委托各生成一张凭证格，左上角带**委托序号**（四张同形凭证原本难辨）。
- 数量统一走**右下角角标**：≤999 直显，再多写 `999+`；0 时整格压暗。
- 格子底色按材料自身的颜色起**径向渐变**，底边压一条同色实线，图标 32×32 矢量（`src/data/data-mat-icons.js`，17 枚：材料 / 玄晶 / 丹药 / 凭证），缩到 20px 仍认得出。
- 悬停（触屏点按）走统一提示框，写名称、来源与用途。

## 二、八页签主菜单

原来八个入口各开一个浮层、在 HUD 右下一字排开，屏幕被切得零碎，还隐含「行囊开着、天赋打不开」这种互斥。

- 新增 `#menuPanel`：左列竖排页签（**行囊 / 道途 / 天赋 / 术法 / 山海志 / 炼器台 / 存档 / 设置**），右列只挂当前页。HUD 上从 **8 个按钮收成 2 个**（行囊 I、菜单 Tab）。
- 实现是**搬 DOM**：`menuMount(id)` 把原面板 `appendChild` 进 `#menuBody` 并加 `.embed`，`menuUnmount()` 送回 `#panelHome`。于是各面板的 CSS、事件委托、探针选择器**全部原样复用**，不必为「嵌入模式」重写一遍渲染。
- 旧入口全部重定向到页签：`toggleInv / toggleStat / toggleQuest / toggleTalent / toggleSkill / toggleForge / openSettings / SaveUI.open`；`I C T K L R P O` 仍是直达对应页，`Tab` 开合菜单，`Esc` 逐层退出（先关菜单，再`closeAll`）。
- 触屏：页签翻成顶部**横排可横滚**，内容区整块滚动，面板 98vw × 92dvh。

### 顺手修掉的一个坑

天赋轮盘进菜单后一片空白。原因是 `renderTalentPanel` **先画后绑定**——`bindTalentCanvas()` 首次执行时设 `cv.width = 660 * dpr`，而改 `width` 会**清空画布位图**，于是刚画的轮盘当场被抹掉；以前面板每次打开都会重绘两次，把这个问题盖住了，收成菜单后首帧只渲染一次就露了出来。现在顺序倒过来（先定尺寸、再画），并把尺寸逻辑抽成幂等的 `sizeTalentCanvas()`，另加 `resize` 重绘与触屏按容器宽等比缩放。

## 三、匠材与打造

**九种匠材**，不占行囊格（与玄晶、符文同库 `state.stash.mats`，键前缀 `craft_`），落在地上是一枚带淡光柱的八面体，走过去自动拾取：

| 档 | 匠材 | 来源 |
| --- | --- | --- |
| 凡料 | 玄铁锭 · 妖兽皮 · 妖骨 | 普通怪 `30% × 掉落倍率` |
| 灵料 | 灵蚕丝 · 赤炎砂 · 寒玉髓 | 精英怪**必出**（不出神料） |
| 神料 | 玄鳞 · 陨星铁 · 妖丹 | **只有 Boss**，一次至少两种并含神料 |

山海套（`seeker`）的掉落数量 ×1.5。

**锻造**在炼器台新增「锻造」页：选一件白装（凡品）或蓝装（灵品）当胚，配匠材与铜钱，重铸成同部位、同等级、同职业的更高品质装备。

- **5 档配方**贴基底等级走（1–8 / 9–16 / 17–24 / 25–32 / 33–40），每档换料加价：铜钱 400 / 1,200 / 2,600 / 4,800 / 8,000。
- **底子越好越省料**：蓝装胚匠材与铜钱按 **6 折**（每种至少 1 个，不能白送）。
- **兵刃另加料**：武器与副手额外要**玄鳞 + 陨星铁**——甲可以省，刃不能省。
- **成品品质**：白装胚 **100% 灵品**；蓝装胚 **62% 玄品 / 26% 神兵 / 12% 套装**。**不产法器**（法器只能掉），套装件沿用既有套装体系。
- 界面把「胚 → 成品概率」画成箭头，下接需求格：够的写 `拥有 / 需要`，不够整格描红、按钮置灰，并直书「还差：赤炎砂、玄鳞」。
- 结算一次完成：校验 → 扣料扣钱 → `rollItem(ilvl, {slot, cls, rarity, noRelic:true})` → `normalizeItem` → 原地替换 `inventory[index]`；异常路径退款兜底。
- 炼器台底部说明随页签切换（`#forgeHint`），不再各页共用一句「符文镶嵌」文案。

## 四、数值与存档

- 匠材存在既有 `state.stash.mats`，**不进 `SaveManager` 的槽位表**，读旧档不报错、也不丢。
- 锻造只改 `inventory[index]`，不碰装备位与孔位/符文以外的结构；成品走 `normalizeItem`，与掉落同一条正规化路径。
- 容量判定仍一律走 `Game.bagCap()`，新代码未新增直接读 `state.maxInv` 的分支。
