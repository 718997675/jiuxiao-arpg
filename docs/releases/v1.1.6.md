# v1.1.6 · 固定词条与可洗词条

发布日期：2026-10-23

## 词条拆成两类

装备的词条从原来的单一列表拆成互不干扰的两组：

| 类型 | 存放位置 | 谁能改它 |
| --- | --- | --- |
| **固定初始词条** | `item.fixed` | 谁都不能。洗练、强化、改为指定词条全部跳过 |
| **可洗练词条** | `item.affixes` | 洗练 / 强化 / 定向洗炼只作用在这一组 |

两者只在属性汇总（`sumItemStats`）、评分（`itemStatMap`）、战力与售价时合并计算。掉落时共用一个已占用 key 池，所以同一件装备不会出现两条相同属性。

## 品质决定固定条数

| 品质 | 固定词条 | 可洗练词条 |
| --- | --- | --- |
| 凡品 | 0 | 0 |
| 灵品 | 1 | 2 |
| 玄品 | 2 | 3（半数情况 4） |
| 神兵 | 3 | 4 |
| 套装 | 2 | 3（四成情况 4） |
| 传世 | 0 | 0 |

可洗练词条的条数与 v1.1.5 完全一致，**固定词条是额外新增的**，不会挤占原有洗练空间。

## 数值为什么打 6 折

固定词条用和随机词条同一套 key / 品阶池生成，但数值乘 `FORGE.fixedMul = 0.6`。

原因是它们锁死了、洗不动：如果给足量，高品质装备一掉出来就能压过玩家辛苦洗了十几次的属性，洗练的意义会被架空。6 折让它成为「这件装备的底子」，而不是「一步到位」。

实测 30 级神兵：固定词条均值 12.1，可洗词条均值 21.4。

## 传世为什么不参与

传世装备的固定属性早就走 `uniqueStats`（按目录定义区间 roll，随 ilvl 每级 +2% 成长）。如果再叠一层 `fixed`，同一件装备会被算两遍。因此 `fixedAffixCount()` 对 `unique` 直接返回 0。

## 界面

- **装备提示框**：固定词条在上、带暗金「固定」小标签，与下方可洗词条之间有一条渐隐分隔线，一眼能看出哪些是洗得动的。
- **炼器台洗练页**：固定词条逐条列出并标注「不可洗练」，右侧没有按钮；只有可洗词条带「洗练 / 定向」按钮。
- **炼器台左侧列表**：词缀统计从「N 条词缀」改成「N 条可洗 · M 条固定」。
- **强化页**：固定词条同样只读展示，标题注明「固定词条不参与强化」。

## 兼容性

- **旧存档自动补齐**：v1.1.5 及更早的装备没有 `fixed` 字段，读档时 `normalizeItem()` 按当前品质补到应有条数，并避开已有可洗词条占用的 key。老存档里的玄品、神兵会在读档后凭空多出 2~3 条固定词条——这是规则统一的结果，不是 bug。
- **品质提升**：凡品→灵品→玄品→神兵 的升级路径上，每提升一档都会调用 `fillFixedAffixes()` 补足固定词条。
- **套装打造**：套装档位（2 条）与原品质不同时自动补齐，已有的固定词条一条不删。
- 存档格式向后兼容，`fixed` 随装备对象整体 JSON 序列化，不需要改 `save.js`。

## 技术改动

- `src/data/data-core.js`：`RARITY` 每档新增 `fixed` 字段。
- `src/data/data-items.js`：`FORGE.fixedMul = 0.6`。
- `src/items.js`：新增 `fixedAffixCount()` / `itemFixed()` / `makeFixedAffix()` / `fillFixedAffixes()`；`rollItem` 先生成固定词条再生成可洗词条；`normalizeItem` 校验与旧档补齐；`sumItemStats` / `itemStatMap` / `itemPower` / `itemValue` 计入固定词条；`reforgeAffix` / `reforgeTargets` / `enhanceItem` / `craftSetItem` 的已占用 key 池纳入固定词条；`itemTooltip` 分区渲染。
- `src/game.js`：品质提升时补固定词条；定向洗炼的重复 key 检查纳入固定词条。
- `src/ui-forge.js`：洗练页与强化页展示固定词条（只读），左侧列表文案区分两类。
- `index.html`：`.tt-faff` / `.tt-faff-tag` / `.tt-aff-sep` / `.faff-fixed` / `.faff-tag` 样式。
