## 发版流程

每次改动落地时的完整动作，缺一不可：

1. **提交**：`feat(vX.Y.Z): 标题` / `fix(vX.Y.Z): 标题`，正文分条列出改动与验证结果。
2. **打附注 tag**：`git tag -a vX.Y.Z -m "vX.Y.Z: 短主题"`。
3. **更新本表**：在最上方加一行，并改「当前版本」。
4. **写版本说明**：`docs/releases/vX.Y.Z.md`，照既有格式（标题 / 发布日期 / 按主题分节 / 验证）。
5. **建 GitHub Release**：`GH_TOKEN=... bash dev/make-release.sh vX.Y.Z "标题"`
   —— Release 条目和 git tag 是两回事，只推 tag 不会在 Releases 页面出现新版本。

推送 `dev-v3`、工作分支与 tag 也属于第 5 步之前必须完成的动作，Release 的 tag 必须已在远程存在。
