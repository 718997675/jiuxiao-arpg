# 技能特效升级计划 · 签名特效 / 元素语言 / 技能组合 / HUD 增益图标

> 状态：**待拍板 · 未动一行代码**
> 提出：2026-10-27 ｜ 分支：`feat/skill-refactor`（已完成 P0 / P1 / P1b：5 槽位 × 三职业）
> 关系：本方案是 `docs/SKILL-REDESIGN-PLAN.md` 的**表现层配套**，不改变任何数值与判定口径。
> 前置：技能重构的地基（5 个功能位 = `SKILL_ARCHETYPE`）已经落地，本方案直接按 5 槽 × 3 职业排特效，不再按老的 36 技能排。

## 0. 一句话

**现在的特效不是"做得不够"，是"全都长一个样"** —— 每个技能都是「地面一个环 + 一簇方块粒子」，
所以旋风斩不像旋转、雷电像一根绳子、领域只有颜色区别。

本方案做四件事，按代价从低到高：

1. **换地基**：粒子从「方块」换成「贴图光斑」，特效从「平躺一张图」变成「有体积、有前中后三段」。
2. **定身份**：15 个技能各有一条**签名剪影**（不看颜色也能认出来），形与色分离，`15 + 6` 而不是 `15 × 6 = 90` 套手写特效。
3. **给组合**：技能连携与元素反应各有一套专属视觉语言。
4. **修 HUD**：增益图标搬到血条下方，**增量更新**（现在每 100ms 重建一次 DOM，这就是闪烁的根因）。

## 1. 现状体检（全部是代码事实，不是感觉）

### 1.1 表现层总共只有 6 个原语（其余都是它们的变体）

| 原语 | 实现 | 出处 | 问题 |
|---|---|---|---|
| `FX.burst` | `THREE.Points` + `PointsMaterial`，**无 map** | `fx.js:352-402` | 粒子是**没有贴图的方块**，暗场景下像灰尘或碎屑 |
| `FX.ring` | `RingGeometry` 躺平在 `y=0.08` | `fx.js:408-417` | 永远是**地面一个扩张环**，没有高度 |
| `FX.flashCircle` | `CircleGeometry` 地面圆片 | `fx.js:419-428` | 同上，纯色块 |
| `FX.area` | 地面圆片 + 边沿亮圈 | `fx.js:444-460` | **所有领域长一样**，只换颜色 |
| `FX.beam` | `THREE.Line` + 8 段随机抖动 | `fx.js:462-476` | 雷电是**一根折线**，不是闪电 |
| `FX.slash` | 环形扇面躺在 `y=0.6` | `fx.js:479-489` | 刀光是**地上的一块扇形**，不是刀气 |

**没有**：贴图粒子、拖尾、体积、贴花、屏幕级反馈、Shader 材质、实例化。`lib/three.min.js` 是 r128 单文件，**没有 EffectComposer**，后处理要自己写。

### 1.2 技能实际调用的特效量少得惊人

`whirl`（旋风斩）整段只有 3 行表现代码（`game.js:3072-3095`）：

```js
FX.ring(pp, rad, 0xffd8a0, 0.4);            // 一个外扩圆环
FX.spark(new THREE.Vector3(pp.x, 1, pp.z), 0xffd8a0, 18);   // 一簇白色方块
this.shake = 0.25; this.hitstop = 60;
```

**没有任何东西在转。** 动作层给了 `actor.atkType = 'spin'`（角色模型在转），特效层却只画了一个外扩环 —— 玩家看到的是"人转了一下 + 地上冒出个圈"，脑子里的"旋风斩"根本没有被画出来。

### 1.3 为什么"领域就是一个圆圈没有辨识度"

因为 `FX.area` 就是**一个地面圆片 + 一个边沿环**。太极、火墙、毒雾、雷云、剑阵五个领域，
代码走的同一条路径，唯一的差别是 `color` 参数。颜色一多，玩家反而分不清。

### 1.4 为什么"雷电 / 火焰感觉不出来"

- 雷：`FX.beam` 是 8 段线，`linewidth` 在 WebGL 里**永远无效**（这是 three 的已知限制），所以它只有 1px 粗，看起来像根线头。
- 火：只有 `FX.flashCircle`（地面橙片）+ 粒子方块，**没有火舌形状、没有热浪、没有余烬上升、没有焦痕**。
- 两者都缺"命中瞬间的强反馈"：没有闪白、没有局部亮度跳变、没有分叉电弧。

### 1.5 相机是高俯角 → **垂直方向的东西才显眼**

相机 `PerspectiveCamera(46, ...)` 且从高处俯视（截图实测约 50°）。
在这个角度下，**躺在地上的一层薄片最不占屏幕面积**，竖直方向的柱、墙、上升气流最占面积。
现在所有特效都躺在地上 —— 这是"看起来没东西"的几何原因，也是本方案所有原语都强调"有体积"的理由。

### 1.6 buff 条：闪烁的根因已经定位

`UI.renderBuffs()`（`ui.js:1296-1315`）：

```js
const sig = list.map(b => `${b.name}|${b.type}|${Math.ceil((Number(b.dur)||0)*10)}|${b.color}`).join(';');
if (sig === this._buffSig) return;
this._buffSig = sig;
el.innerHTML = list.map(...).join('');        // 全量重建
```

- `Math.ceil(dur*10)` → **签名每 100ms 变一次** → `innerHTML` 每秒重建 10 次。
- 而 `renderBuffs()` 在 `game.js:2585` **每帧被调用**。
- 每次重建，`.buff{animation:buffIn .18s}`（`index.html:133`）**都会重播** → 这就是**闪烁**。
- 结果是"DOM 抖动 + 入场动画重播 + 布局反复重排"三件事绑在一起。

**这是纯实现问题，不是设计问题**，修起来很便宜（见 §6）。

### 1.7 一个好消息：特效 DSL 已经存在

`src/data/data-form-fx.js`（260 行）已经有"**11 种打法风格（+1 个 plain 空档）× 6 种原语**"的声明式配方，
由 `Game.castFormFx()`（`skill-beh.js:1461-1503`）解释执行，只画表现、不碰判定。

这套思路是对的，本方案**不另起炉灶**，而是把它升级成 v2：
补原语、补三段（起手/持续/命中）、补元素槽、补台阶 patch，并让**技能本体特效也走同一套解释器**
（项目里踩过"两套并存互相打架"的坑，见 `AGENTS.md`）。

## 2. 三条不可妥协的硬指标

先定验收，再谈做法。

| 指标 | 定义 | 测法 |
|---|---|---|
| **辨识度** | 同职业 5 个技能的高光截图，遮住 UI 与颜色，**能认出 ≥4 个** | `dev/vfx-shot.js` 逐技能出图 + 灰度版 |
| **性能预算** | 单技能特效 ≤ 6 draw call；5 技能连放峰值 ≤ 基线 +25%；移动端不掉到 30fps 以下 | `dev/vfx-bench.js` 读 `Game.renderer.info.render.calls` 与帧时 p95 |
| **一致性** | 同一元素在不同技能里必须用同一套"材质语言"（色值/贴图/残留贴花） | 人工核对 `ELEM_PROFILE` 表 |

> 辨识度的判定口径：**"能不能靠剪影认出来，而不是靠颜色"**。
> 火球和火墙都是橙色，但如果剪影一个是"飞出去的光球 + 拖尾"、一个是"一排竖直火舌墙"，就不会混。

## 3. 架构：形 / 色 / 时 三层分离

这是整份方案的**核心工程决策**，直接决定工作量是 15 套还是 90 套。

```
                 ┌──────────────────────────────────────┐
  技能身份 ──────▶ │  SKILL_VFX[id].sil   （剪影，15 套）   │  形：招式长什么样
                 └──────────────────────────────────────┘
                              ×
                 ┌──────────────────────────────────────┐
  元素注入 ──────▶ │  ELEM_PROFILE[elem]  （材质，6 套）    │  色：光斑/残留/音色/重力
                 └──────────────────────────────────────┘
                              ↓
                 ┌──────────────────────────────────────┐
  时间轴 ────────▶ │  cast → loop → impact → aftermath     │  时：三段节奏 + 顿帧/闪白
                 └──────────────────────────────────────┘
                              ↓
                 ┌──────────────────────────────────────┐
  组合层 ────────▶ │  COMBO_FX[rule]      （组合，~14 条）  │  连携：技能 × 技能、元素 × 元素
                 └──────────────────────────────────────┘
```

**为什么形色分离能省 6 倍工作量**：
`SKILL-REDESIGN-PLAN` 里估过「6 元素 × 5 槽 × 3 职业 = 90 种组合」会爆炸。
分离之后，元素**不参与剪影**，只提供三样东西 —— 贴图集、色值、残留贴花。
所以 90 种组合 = 15 条剪影 × 6 份材质配置，**手写量 15 + 6**。
元素混搭（主 70% / 副 30%，见重构方案 §6.1）由解释器在播放时对配方做浅拷贝染色，天然成立。

**台阶（Lv5 / Lv10 进化）用 patch，不用 copy**：

```js
SKILL_VFX.whirl = {
  sil: 'spin',                       // 剪影标签
  color: 'elem',                     // 主色取元素
  tex: 'elem',                       // 粒子贴图取元素
  decal: 'elem',
  cast:   [ {t:'arc', n:2, tilt:.35} ],
  loop:   [ {t:'vortex', r:2.2, dur:0.6} ],
  impact: [ {t:'shock', r:1.2}, {t:'spr', n:10, tex:'spark'} ],
  tiers: {                           // 只写差异，不重写整条
    5:  { loop:[{t:'vortex', r:2.8, dur:0.6, helix:2}] },   // 可移动 → 螺旋更宽
    9:  { cast:[{t:'arc', n:4, tilt:.35}], decal:'scorch' } // 吸怪 → 四刀 + 焦痕
  }
};
```

## 4. 原语层：FXKit v2（11 个新原语）

每个原语都要能**在低画质档退化成简版**（`FX.q < 1`），否则手机上必崩。

| 原语 | 视觉语义 | 实现要点（r128 可做） | 降级（低画质） |
|---|---|---|---|
| `spr(pos,opt)` | 贴图光斑粒子 | `PointsMaterial.map` 取图集；`size`/`life`/`grav` 逐簇可调 | 点数减半 |
| `trail(points,opt)` | 带状拖尾 / 刀光余影 | `BufferGeometry` 双排顶点 + uv 沿 t 拉伸，逐帧写位置 | 退化为 3 颗 `spr` |
| `bolt(a,b,opt)` | 折线闪电（带分叉） | 中点位移递归 `depth=4` + 30% 概率分叉；两条叠加（外晕/内芯） | 直接一段线 + 端点闪光 |
| `arc(pos,opt)` | 立体刀光 | 环形扇面**倾斜 ~35°** + 内外双弧；**父 Group 绕 Y 轴转、子 Mesh 只管倾斜**（同一 mesh 叠两次欧拉角会互相干扰） | 只留外弧 |
| `shock(pos,r,opt)` | 冲击波 | 地面环（快）+ 竖直气浪薄片（慢，0.25s）+ 尘环（`spr`，正重力） | 地面环 + 尘 |
| `vortex(pos,opt)` | 螺旋上升气流 | 每颗粒子记角度，逐帧 `angle += ω`、`y += v`，在 `Points` 顶点里算 | 只留 1 圈 |
| `field(pos,opt)` | **领域**（地面纹 + 边界墙 + 体积柱 + 脉冲） | 4 件套：地面旋转符文纹理、边界粒子墙（每 0.3s 从边缘升起）、中央半透明柱（`CylinderGeometry`，`depthWrite:false`）、2 秒一次的脉冲环 | 去柱、去墙，只留地面纹 + 脉冲 |
| `cone(pos,dir,opt)` | 扇形喷射（火/毒/冰） | 沿锥体内随机撒 `spr`，速度朝外偏上，重力负 | 点数减半 |
| `geyser(pos,opt)` | 地面喷发柱（落雷/火柱/冰刺） | 竖直薄片 × 3（不同角度）交叉 + 底部白闪 + 顶端粒子 | 单薄片 |
| `decal(pos,opt)` | 贴花残留（焦痕/霜/毒斑/裂痕） | **16 个 quad 的固定池循环复用**，不新建几何；3~6 秒淡出 | 池减到 6 个 |
| `enchant(on)` | 武器附魔（近战元素） | 剑身绑 `trail` + 每 0.2s 一颗 `spr`，随武器骨骼走 | 只留发光 |

**所有原语的共同约束**（写进代码注释，防止后人加回来）：

- **不挂 `PointLight`** —— 一次挂灯 = 全部材质重编译，`fx.js:527-531` 已经踩过这个坑。
- **不 new 材质** —— 材质按「图集 + 混合模式 + 参数档」缓存，同类复用。
- **不在 `update` 里 new `Vector3`/`Color`** —— 用模块级复用对象（现有代码已这么做，保持）。
- 几何体沿用 `_fxGeo` 缓存约定（`fx.js:256-268`）。

### 4.1 贴图图集（一次生成，全局共用）

`fxAtlas()` 用 Canvas 程序化画一张 **512×512 / 16 格 128×128** 的图集，
和现在 `talismanTexture()`（`fx.js:275-336`）同一套做法，不引入任何素材文件：

| 格 | 内容 | 画法 |
|---|---|---|
| soft | 径向柔光 | `createRadialGradient`，中心白 → 边缘透明 |
| spark | 四芒星 | 两条渐变细十字 |
| ember | 小火点 | 小圆 + 外扩噪声 |
| smoke | 烟团 | 多层不规则圆弧 + 低 alpha |
| shard | 冰晶 | 六边形 + 内高光 |
| ring | 细环 | `arc` 描边 + 模糊 |
| slash | 月牙 | 两段贝塞尔围成的月牙 + 内亮边 |
| rune | 符文 | 复用 `talismanTexture` 的笔画风格，画 3 种 |
| dust | 尘土 | 噪声团 |
| star | 大四芒（暴击） | 长十字 + 中心亮核 |

> 图集的意义：**一个贴图 = 一次纹理绑定**。如果每簇粒子各带一张图，draw call 不会爆但材质切换会。
> 图集 + 单材质是"画面变好看但没变慢"的关键。

## 5. 时间轴：三段式（这是"手感"的真正来源）

同一个特效，粒子数不变，**只改时间曲线**，手感差别能到"廉价/高级"两档。

| 段 | 时长 | 做什么 | 为什么必须有 |
|---|---|---|---|
| **起手 anticipation** | 60~150ms | 光向落点收束、脚下微光、角色前摇 | 没有起手 = "突然出现"，玩家来不及把它和按键对应上 |
| **命中 impact** | 40~80ms | 闪白（局部，不是全屏）+ 顿帧 + 冲击波 + 震屏 | 这是"打到了"的唯一证据。现在只有 60ms 顿帧，没有视觉同步 |
| **余韵 aftermath** | 200~600ms | 残留贴花、上升余烬、烟、边缘光衰减 | 没有余韵 = 特效消失得太干净，世界像没被打过 |

**分级表**（按伤害量级自动选档，避免每个技能手调）：

| 档 | 例 | 顿帧 | 震屏 | 闪白 | 贴花 |
|---|---|---|---|---|---|
| 轻（普攻 / ① 号位） | 连斩 | 0 | 0.12 | 无 | 无 |
| 中（②③ 号位） | 裂地 / 剑阵 | 60ms | 0.25 | 局部 40ms | 焦痕 3s |
| 重（④ 护盾破了 / ⑤ 终结） | 断岳斩 / 法相 | 90ms | 0.4 | 局部 80ms + 边缘暗角 | 裂痕 6s |

**禁止**：全屏白闪。现在是暗色国风场景，全屏闪白一次会让玩家眨眼，
而且和 `#vignette`（受伤红晕）打架。闪白只允许发生在**落点半径内**。

## 6. HUD：增益图标搬到血条下方（独立可上线，先做这个）

用户明确要的三件事：**图标形式**、**血条下面**、**取消技能栏上方**、**不闪烁**。

改成：**放进 `#charplate`**（`index.html:2341`），作为血条区 `.bars` 的下一行。

```html
<div id="charplate">
  <div id="portrait">…</div>
  <div class="bars">…hp / mp / xp…</div>
  <div id="buffrow"></div>      <!-- 新增：flex-basis:100% 换行 -->
</div>
```

```css
#charplate{flex-wrap:wrap}
#buffrow{flex-basis:100%;margin-left:76px;margin-top:6px;
  display:flex;flex-wrap:wrap;gap:4px;pointer-events:auto}
```

- 宽度天然对齐血条（`.bars` 是 238px），不新增悬浮层。
- 进菜单 / 开局界面自动跟着 `#charplate` 一起淡出（`body.in-menu` 那条规则已覆盖，不用再加）。
- **删掉** `#buffbar` 的 DOM、CSS，以及 `ui.js:1297`、`mobile.js:418`、`index.html:1588/1591/1919` 五处引用。

### 6.2 与「无尽试炼」面板的冲突（必须处理）

`#trialHud` 在 `left:18px; top:96px; width:238px`（`index.html:2172`）——
**正好压在血条下方**。buff 行不能让试炼面板盖住。

buff 行最多两行（约 44px），超过就折叠成 `+N`。

### 6.3 图标规范（沿用 M11，不新造一套）

`src/data/data-icons.js` 的硬规范照抄：`viewBox="0 0 32 32"`、纯 `path`、`fill="currentColor"`。
新建 `src/data/data-buff-icons.js`，约 16 枚：

| 类 | 图标 key | 视觉 |
|---|---|---|
| 增益 | `atk_up` / `aspd_up` / `spd_up` / `crit_up` / `dr_up` / `shield` / `regen` / `invuln` / `thorns` / `cdr` | 箭头、盾、心、光罩、刺环 —— **符号，不画具象物** |
| 减益 | `slow` / `freeze` / `poison` / `burn` / `vuln` / `shred` / `noheal` | 冻结用雪花边、中毒用滴落、易伤用裂口 |

**关键约束：buff 图标不能画成技能图标**。技能图标是"具象物"（符纸/剑/火球），
buff 图标必须是"符号"（箭头/盾/滴），否则玩家会以为是技能位。

映射走一张表，兜底保留现有的"取名字首字"逻辑（不要因为新图标缺一个就让 UI 空掉）：

```js
BUFF_ICON_OF = {   // 现有 buff key → 图标
  'skill:bloodrage': 'atk_up', 'skill:shieldwall': 'shield',
  'beh:锐意': 'crit_up', 'beh:疾行': 'spd_up', 'beh:冰缓': 'slow', … 
};
```

### 6.4 叠层（"多个 buff 叠加同时显示"）

现在叠层是**把层数写进名字**（`skill-beh.js:402`：`'战意 ×' + n`），
结果同一个 buff 每次叠层都换一个 name，图标和排序全跟着抖。

改成给 buff 加**结构化字段**：

```js
addBuff(name, stats, color, { key:'beh:stack:whirl', stacks:3, maxStacks:5, icon:'atk_up' })
```

- 图标右下角 `×3` 角标；满层时外框加一层静态金边（**不闪**）。
- 同 `key` 的 buff 只占一个位置，刷新时长而不新占位。
- 不同 key 的 buff 全部同时显示（这就是用户要的"同时显示、消失则跟着消失"）。

### 6.5 去闪烁：三条硬规则

| 规则 | 做法 |
|---|---|
| **不重建 DOM** | `renderBuffs()` 改成增量 diff：`Map<key, el>`，只增/删/改。**禁止 `innerHTML =`** |
| **不每帧算签名** | 签名里去掉 `Math.ceil(dur*10)`，只保留 `key|type|color|stacks`；时长变化走**独立通道**（见下） |
| **不重播入场动画** | 入场 `.in` class 只加一次；刷新时只做 border 高亮过渡，不重放 `@keyframes` |

时长显示：**每秒更新一次**（在 `Math.floor(dur)` 变化时才写样式），
用底部 1px 进度条 + `transition: width 1s linear` —— 视觉上连续，DOM 只写 1 次/秒。

到期：**先加 `.out`（200ms 收缩淡出）再从 DOM 移除**。现在到期瞬间直接消失，看起来像"闪了一下"。

### 6.6 上限与排序

- 最多显示 **8 个**，超出折叠为 `+N`（点一下展开成两行，只在需要时）。
- 排序：**增益 → 减益 → debuff 置后**（沿用现有口径 `ui.js:1302`），组内按剩余时间升序（快没了的靠后，不跳动）。
- 色盲兜底：debuff 用**虚线边框 + 左上缺角**，不只靠红色。

### 7.1 刀客 —— 近战 / 怒气 / 兵形

**旋风斩专门说清楚（用户点名的）**：

现在的实现是"外扩一个圈"。改成 ——
1. 角色 `atkType='spin'`（已有）继续转；
2. 加 **2 道倾斜 35° 的刀气弧**，挂在同一个父 Group 上，父 Group 绕 Y 轴匀速转（约 12 rad/s），
   两弧在父级里错开 180° —— **旋转发生在父级，倾斜发生在子级**，不要在同一个 mesh 上既 `rotation.x` 又 `rotation.y`（欧拉角顺序会把弧甩平）；
3. 刀气弧**内外双弧**（外弧亮、内弧淡），加 `trail` 余影；
4. 脚下 `vortex`：粒子角度逐帧递增、高度上升 —— 形成"龙卷"；
5. 命中瞬间 `shock(1.2)` 小冲击 + 每命中一个敌人向中心拉一条 `spr` 流线（**这就是"吸怪"的视觉**，数值上是击退/聚怪，视觉上必须能看出来）。

## 10. 技术选型：要不要引入新东西（用户第 4 条）

结论：**引入，但只引入"便宜且必赚"的三样，后处理列为可选。**

| 技术 | 值不值 | 理由 | 结论 |
|---|---|---|---|
| **贴图化粒子（图集）** | ★★★★★ | 半天工作量，全局从"方块"变"光斑"，是所有改造里性价比最高的 | **必做（V0）** |
| **Ribbon 拖尾** | ★★★★★ | 刀光/投射物/武器附魔全靠它，"看起来贵"的主要来源 | **必做（V0）** |
| **折线闪电 `bolt`** | ★★★★★ | 现在雷电是一根 1px 线（`linewidth` 在 WebGL 无效），改完立竿见影 | **必做（V0）** |
| **ShaderMaterial（内联 GLSL）** | ★★★☆ | r128 支持。只用在两处：①领域地面纹的 uv 流动；②贴花边缘软化。**不重写渲染管线** | **选做（V3）** |
| **InstancedMesh** | ★★★☆ | 剑影、符文、落雷这类"同形状多个"，能把 N 次绘制压到 1 次 | **选做（V2，先量后上）** |
| **自制 Bloom（全屏后处理）** | ★★ | 没有 EffectComposer，要手写 RT + 降采样模糊 + 叠加；移动端成本高，且和现有 `toneMapping: NoToneMapping` 冲突要调 | **不做默认，PC 高档可选** |
| **假 Bloom（多层 additive halo）** | ★★★★ | 现在投射物已有 2 层 halo（`fx.js:532-535`），贴图化后叠 3 层就能骗过眼睛，成本 = 2 个 draw call | **必做（V0）** |
| **贴花池（decal）** | ★★★★ | 焦痕/霜/毒斑让"世界被打过"，16 个 quad 固定复用，成本恒定 | **必做（V2）** |
| **屏幕级反馈（闪白/暗角/色差）** | ★★★ | 闪白与暗角**局部**做（`FX` 层），色差需要后处理 → 跳过 | **部分做** |
| **物理引擎（刚体碰撞）** | ★ | 本项目无刚体，敌人位移是直接改 `pos`；引入物理只为"碎块飞散"不划算 | **不做** |
| **粒子系统库（如 Proton/three-nebula）** | ★ | 会突破"零依赖"约束，且与现有 `FX` 池化逻辑冲突 | **不做** |
| **GSAP 之类时间轴库** | ★ | 三段式用 `FX.zones` 里现成的 `life/max + 插值` 就够，不必引库 | **不做** |

**一句话**：不需要引入任何第三方库。**贴图 + 拖尾 + 折线 + 贴花 + 假 bloom** 五样做扎实，
观感能从"学生作业"到"能看"；真正的分水岭是**形/色分离**和**三段式时间轴**这两个设计决定，不是技术栈。

## 11. 性能预算与降级

现在的约束（都在代码里）：`setPixelRatio(min(dpr,1.5))`、`shadowMap.enabled=true`、
`FX.parts` 上限 40 组、`FX.q` 按帧率自动下调（`fx.js:346`）、`Game._calls` 自数 draw call（`game.js:197-204`）。

| 指标 | 预算 | 超了怎么办 |
|---|---|---|
| 单技能 draw call | ≤ 6 | 合并同材质原语；`spr` 必须一个 `Points` 一批 |
| 5 技能连放峰值 | ≤ 基线 +25% | 用 `dev/vfx-bench.js` 先测基线（现在大约 200~400，因场景而异） |
| 每帧新建材质 | **0** | 材质缓存表；`dispose` 规则沿用 `fx.js:684-713` |
| 粒子簇 | ≤ 40 组（沿用） | 优先砍"远处/小尺寸"的 |
| 移动端 | ≥ 30fps | `FX.q<1` 时每个原语走降级分支（§4 最后一列） |

**降级表（写进代码，不靠临时判断）**：

| 档 | 粒子数 | 拖尾 | 贴花 | 假 bloom 层数 | bolt 分叉 |
|---|---|---|---|---|---|
| 高 | 100% | 开 | 16 | 3 | 2 层递归 |
| 中 | 60% | 开 | 8 | 2 | 1 层 |
| 低 | 35% | 关 | 0 | 1 | 无 |

| **V3 · 签名（法师 + 道士）** | 10 个签名 + 领域 `field` + 召唤/法相/兵形 | 三职业齐 | 3~4 天 |
| **V4 · 元素语言** | `ELEM_PROFILE` 6 套 + 染色解释器 + 近战附魔 | 15×6 矩阵自动成立 | 2~3 天 |
| **V5 · 组合** | §9.1 技能内组合（现在就能做）→ §9.2 元素反应（等 P3）→ §9.3 核心连携（等 P4） | 随重构主线推进 | 2~3 天 |
| **V6 · 打磨** | 音效三段对齐、低画质降级核验、回归与录屏对比 | — | 1~2 天 |

**建议顺序**：`V1（HUD，独立、用户点名、见效最快）` → `V0` → `V2` → `V3` → `V4` → `V5`。

> 与重构主线的**依赖关系**：
> V1 / V0 / V2 / V3 **不依赖** P2~P4，可随时开工；
> V4 的"元素注入"要靠 P3 的 `elem` 标记（但可以先用 `SKILLS[id].elem` 顶着）；
> V5 的 §9.2 要等 P3，§9.3 要等 P4。
> **不要**在 P3 之前手工维护"元素 → 特效"的分支表，那就是将来要拆的东西。

## 14. 风险与反例

| 风险 | 会怎么出事 | 对策 |
|---|---|---|
| **特效过亮挡住战斗** | 5 个技能同屏 = 看不清怪的攻击预警（`FX.telegraph` 会被盖住） | 亮度预算：特效 alpha ≤ 0.75；伤害数字永远最上层；同屏只允许 1 个全屏级闪白；`telegraph` 渲染顺序永久最高 |
| **移动端掉帧** | 贴图粒子 + 拖尾在集显上是真成本 | 原语级降级表（§11）+ `FX.q` 联动；移动端默认"中"档 |
| **工作量爆炸** | 15 技能 × 6 元素 × 3 台阶 = 270 种画面 | 形/色分离（15+6）+ 台阶 patch（不是 copy） |
| **只做了一半** | 刀客做完、法师道士还是老样子，观感更割裂 | **按职业整批交付**，一批不完整不合 main |
| **改特效把判定改坏** | 顺手调整了半径/位移 | 硬规则：特效层**只读坐标**，不改 `pos`/`dmg`（沿用 `castFormFx` 的口径，`skill-beh.js:1452-1459`） |
| **buff 图标像技能图标** | 玩家以为多了一个技能位 | 图标规范：符号而非具象物（§6.3） |
| **两套特效系统并存** | 变体特效走 `FORM_FX`、技能特效走 `SKILL_VFX`，改一处忘一处 | 合并为**同一解释器** `FX2.play(recipe, ctx)`，`FORM_FX` 作为 `SKILL_VFX` 的一个子集保留 key |
| **后处理上瘾** | 加了 bloom 之后手机直接 20fps | 全屏后处理**默认关闭**，只在 PC 高档且用户手动开启 |

## 16. 一句话总结

现在的问题不是"特效不够"，是**只有一种特效**：所有技能都在地上画一个圈。

改法是**把"形"从"色"里拆出来**：
15 条签名剪影（旋转 / 塌陷 / 轨道 / 升起 / 天降 / 火墙 / 包裹 / 法身 / 符纸 / 剑雨 / 双鱼 / 召唤阵…），
配 6 套元素材质，用**起手 → 命中 → 余韵**三段节奏播出去。

技术上是三件便宜事：**给粒子贴图、给刀光加拖尾、给雷电加分叉**；
再加上一个**不重建 DOM** 的 buff 行。

这三件做完，观感就已经换了一个档；形色分离做完，"每个技能与众不同"才真的成立。
