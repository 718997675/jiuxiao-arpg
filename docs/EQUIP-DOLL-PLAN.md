# 装备模组化计划 · 纸娃娃从「换颜色」到「换零件」

> 状态：**方案稿，未动一行代码**
> 提出：2026-11-02 ｜ 依据：`src/actors.js`（applyPaperDoll / itemVisualColor）、`src/charforge.js`、`src/weapons.js`、`src/data/data-items.js`
> 一句话：**本作没有贴图，所以「素材设计」在这里 = 体块语汇 + 装配规则 + 命名谱系，不是画图。**
> 目标不是「让装备更好看」，是**让玩家隔着 3 米看出对面穿的是什么**，并且这套语汇能跟着版本一直加下去。

---

## 0. 一句话

现在 14 个装备槽里，**有 8 格在模型上什么都不做**；剩下 6 格也只是把同一个几何体换个颜色。
这一版要把它改成：**每件装备 = 一个「模组键」（槽位 × 造型族 × 阶）× 三层拼装**，
拼出来的东西是真正的几何差异，而模组表本身可以一直往上加，不用改一行渲染代码。

## 1. 现状盘点（全部是代码里的事实，可逐条核对）

| 项 | 现状 | 出处 |
|---|---|---|
| 装备槽位 | **14 个**（`SLOT_ORDER`）；武器/副手分职业 | `data-items.js:26` |
| 装备基底 | **384 件** = 护甲 10 槽 × 8 档 × 3 变体 + 武器 72 + 副手 72 | `data-items.js:71` |
| 传世 / 套装 | 40 件 / 18 套 | `data-uniques.js` / `data-items.js` |
| 纸娃娃几何 | **5 个**：头盔 / 护肩 / 披风 / 武器 / 副手 | `actors.js:945` |
| 头盔·护肩·披风几何 | **只按职业三选一，与装备完全无关** —— 8 档 × 3 变体共用同一个几何 | `actors.js:1005-1029` |
| 表现变量 | 3 个数字：`base` / `dark` / `metal` + 1 个发光色 | `itemVisualColor` `actors.js:1112` |
| 第二份纸娃娃 | `applySkelDoll`（GLB 骨骼版）**全仓没有调用点，是死代码** | `skel.js:345` |
| 受击白闪 | 遍历 `a.mats` 逐材质改 emissive | `charforge.js:511` |
| 阴影 | 开（PCF），装备 `castShadow` 会翻倍绘制 | `game.js:279` |

**结论：384 件基底 → 5 个几何体 → 3 个数字。装备的「身份」在画面上几乎不存在。**

### 1.1 六个具体病灶（不是感觉，是能指到行的死代码）

1. **战甲完全没有表现。** `if (chest && !a.cf)`（`actors.js:966`）—— 而 `cf` 三个职业恒为 `true`
   （`charforge.js:149`）。也就是说**玩家换战甲，模型一点变化都没有，颜色都不给**。这条分支从古风角色上线起就是死代码。
2. **披风槽被忽略。** `const capeItem = eq.chest;`（`actors.js:1033`）—— 披风是否出现、什么颜色，
   取决于**战甲的品质**。玩家戴一件传世披风、穿一件白装战甲，背后什么都没有。
3. **护手把「手」染色。** `P.handMat` 是手部皮肤材质（`charforge.js:163`），戴护手 = 两只手变成铁色。
4. **头/肩/披风的形状不看装备。** 三个槽位只有 3 种造型（按职业），8 阶 3 变体一模一样。
5. **腰带 / 项链 / 戒指 ×2 / 法器 / 命格，零表现。** 7 格。
6. **换装泄漏。** `clearGroup` 只 `remove`，不 `dispose`（`actors.js:933`），而 `WeaponForge.build`
   每次新建 geometry + material。**每换一次装漏一把武器和一顶头盔的显存**，换装 50 次就是真机掉帧的起点。

> 第 6 条是这一版必须顺手修的：模组化之后每次换装会重建 10 个挂点，不回收就是 10 倍泄漏。

## 2. 目标与判据

| 目标 | 判据（可测，不是形容词） |
|---|---|
| **可辨认** | 同一槽位三族，**纯黑剪影 IoU < 0.85**；同族跨阶差 ≥ 4 档，剪影像素差 ≥ 8% |
| **全覆盖** | 14 格全部在模型上有几何或明确的光效表现（戒指例外，见 §4.3） |
| **可扩展** | 加一族 = 加一条数据 + 一张图标，**不改渲染代码、不改存档结构** |
| **不花素材** | 零外部资源。几何全部由 `box/cyl/cone/sph/dome/torus` 六种原语拼，纹饰走程序化贴图（可选） |
| **不解释也能懂** | 不看说明，选人界面里三件同类装备放在一起，玩家能指出「这件更重」 |

**反目标**（明确不做）：不改角色比例、不改判定半径、不引入骨骼动画、不做布料模拟、
不做「装备影响移动速度的视觉」（那是数值系统的事）。

## 3. 设计原则

### 3.1 三层辨识度（离摄像机多远，看得到什么）

| 层 | 距离 | 靠什么表达 | 允许变化的部分 |
|---|---|---|---|
| **轮廓** | 3 米（战斗中） | 体量 + 外扩方向 + 尖/方/弧 | 槽位的造型族（三族） |
| **体块** | 1 米（选人 / 商店） | 层数、厚度、覆面比例 | 阶（8 档 → 3 段 LOD） |
| **纹饰** | 0.3 米（图鉴 / 试衣） | 边沿、扣饰、纹样、流苏 | 品质 / 套装 / 传世签名 |

**铁律一：在 3 米这一层没差别的东西等于没做。** 一条只加在 0.3 米层的装饰，只能算 P4 的加分项，
不能算「这个槽位做完了」。

### 3.2 三族必须沿三个不同的轴分开

不许「同一副骨架换两个零件」充数。每族的区分必须同时命中三项中的至少两项：

- **体量轴**：宽 / 厚（重甲比轻裘宽 10~18%）
- **轮廓轴**：尖（兽首/羽）/ 方（札甲）/ 弧（云肩/纱）
- **外扩方向**：向上（冠）/ 向侧（羽肩）/ 向后（重氅）

> 这条是从技能侧那条教训搬过来的：**参数化到「语法」就是换皮**，判据是「动作不重复」，不是「形状不同」。
> 装备这边对应的判据就是「剪影不重合」。

### 3.3 模具骨架 = 三层，不是一根缩放滑杆

「每把剑有个基础骨架，不同剑在骨架上改皮肤 / 扩尺寸 / 加光效」—— 方向是对的，
但**必须先把「骨架」拆成三层**，否则会重演技能侧的翻车（`NSYN` 8 语法参数化到最后每招一样，
整张表删掉）。判据不是「形状不同」，是**剪影不重合**。

| 层 | 内容 | 谁改 | 改动后果 |
|---|---|---|---|
| **契约层** | 握点 `y=0`、刃向 `+y`、柄向 `−y`、厚度朝 `z`、**总长上限** | 谁都不许改 | 改了 → `WPN` 翻腕与 `ATK` 挥砍全部错位 |
| **形制层** | 直刃 / 弧背 / 阔刃 / 长杆 / 盾 —— 轮廓本身 | 加新武器族时 | 只加数据，渲染代码 0 行 |
| **装饰层** | 护手 / 缠绳 / 吞口 / 流苏 / 光效件 | LOD 升阶、品质提升 | 只往数组加件 |

**三种扩展各落一层，代价差两个数量级**：

| 扩展方式 | 落层 | 代价 | 备注 |
|---|---|---|---|
| 改皮肤 | 顶点色通道 | **0 行代码** | 本作没有贴图，「皮肤」= 4 个材质通道 |
| 加光效 | 装饰层 `accent` | 1 条数据 | `emissive` 是材质级 → 必须单独成 mesh |
| 扩尺寸 | 形制层 `w` / `t` | 1 个数字 | ⚠️ **只能非等比，`y` 恒为 1** |

**为什么「扩尺寸」最危险**：它跨了层。刀从 1.40 米改到 1.24 米，是为了「举刀不顶出画面、
劈砍不扎穿地面」（`charforge.js:107` 的注释）。整体 `scale(1.14)` 会同时把武器拉长 14% →
待机姿态刀尖插进地里。所以正确的做法是 **`scale.set(w, 1, t)`：变宽变厚不变长**，
`w/t` 收在 `DOLL_WEAPON_RIG` 里，装饰件反向缩放抵消（否则重刀的流苏也会被拉宽）。

落地见 `data-doll.js` 的 `DOLL_WEAPON_RIG`（形状 × 3 族 × `len/w/t/trim`）
与 `DOLL_WEAPON_TRIM`（5 个形制件）。防具侧同一套思路：**族 = 形制**、**LOD = 装饰**、
**通道色 = 皮肤**，所以 `DOLL_PARTS` 不需要再分一层。

### 3.4 不删身体件，只压暗 + 加壳

`charforge` 的身体是**比例基准**（髋 0.92、胸 1.27、肩 ±0.268、身高 1.88），
动画曲线（`ATK` / `WPN`）全部按这个比例调过。所以装备**永远不替换身体网格**，
只在身体外面套壳，并把被盖住的身体材质压暗成内衬色。

好处：装备再离谱，比例和动作也不会崩；坏处：多一层顶点，接受。

## 4. 模组谱系（33 族）

**模组键 = `槽位 + 造型族 + LOD 段`。** 造型族来自**已有的 `item.baseVar`**（0 均衡 / 1 重防 / 2 轻灵），
不用新增字段、不用改存档 —— 384 件基底天然分成 10 槽 × 3 族。

### 4.1 需要建模的 9 槽 × 3 族 = 27 族

| 槽 | 族 A（均衡·baseVar 0） | 族 B（重防·1） | 族 C（轻灵·2） | 三轴差异（体量/轮廓/方向） |
|---|---|---|---|---|
| **helm** | 巾帻：幅巾 + 后垂带 + 额饰 | 兽面甲：覆面 + 吞口 + 颈后护片 | 立冠：竖冠 + 双簪横穿 + 玉牌 | 贴头 / 前包上突 / 竖向拉高 |
| **chest** | 交领战袍：交领 + 宽袖 + 束腰 + 开衩摆 | 札甲：胸板 + 三排甲片 + 护心镜 + 硬裙甲 | 轻裘：贴身皮甲 + 单肩斜挂 + 短摆 + 腰囊 | 软摆 / 宽厚 / 贴身斜线 |
| **shoulders** | 云肩：两片弧面贴肩 | 板甲肩：三层叠片 + 吞口 + 铆钉 | 羽肩：骨刺外扩上扬 | 弧贴 / 层叠下压 / 上挑外扩 |
| **cloak** | 短氅：及膝、直线 | 重氅：毛领 + 及踝 + 加厚 | 纱氅：双层、长、半透 | 短直 / 厚垂 / 层飘 |
| **gloves** | 布手：袖口翻边 | 臂甲：前臂筒 + 指节三环 + 肘尖 | 缠绳：交叉绑带 + 露指 | 布 / 硬筒 / 线 |
| **boots** | 布履：薄底 + 绑腿布 | 战靴：胫甲片 + 铁头 + 铜扣 | 轻履：露趾 + 交叉带 + 铃 | 平 / 高筒 / 开 |
| **belt** | 腰封：宽布 + 玉扣（现有） | 铜钉带：三排钉 + 垂片 + 大扣 | 细带：双绳 + 玉坠 | 宽平 / 厚垂 / 细 |
| **amulet** | 玉牌：颈环 + 单坠 | 珠串：多珠、摆动 | 铃：金属铃 + 红绳 | 单点 / 多点下垂 / 侧挂 |
| **relic** | 浮珠：腰间绕行 1 颗 | 符板：背后 3 张竖符 | 铃铎：腰侧 3 铃 | 点 / 面 / 串 |

> **族名读法**：A/B/C 是**体块语言**，不是职业。数据的三个变体在语义上略有偏移
> （头盔/项链的 C 偏「法力/暴击」，甲/肩的 C 偏「闪避/移速」），
> 但视觉上都读作「轻」。所以 C 族统一做成「轻、薄、外扩、带飘带」，具体材质由职业覆盖。

### 4.2 只做光效的 2 槽（6 族 → 6 条 2~3 件的短 spec）

| 槽 | 族 A | 族 B | 族 C |
|---|---|---|---|
| **ring（左右各一，共用族）** | 素环：细环 + 一点微光 | 镶石戒：宽环 + 元素色石 | 双环：两环 + 短链 |
| **fate（命格）** | 脚下符纹环（静态） | 背后命盘（半透明旋转） | 双肩各一点命火 |

### 4.3 一个诚实的取舍：戒指在 1.88 米的人身上看不见

戒指直径 2 厘米，正常镜头距离下不到 2 个像素。**所以戒指不做「环」的造型，做「手上的元素光点 +
命中时的一闪」**，颜色取自词缀的元素（火/冰/雷/毒/圣）。省下来的建模预算放到护手和靴子上。

同理：**披风是从背后看的**，正面对战几乎看不到 —— 所以披风的辨识度给「战斗中飘动幅度」，
不给「细节件数」。

## 5. 装配规则

### 5.1 挂点（全部是空 `Group`，遵守 charforge 的「空挂点不放装饰」契约）

| 挂点 | 父节点 | 常驻槽 | 现状 |
|---|---|---|---|
| `helmG` | headG | helm | 有 |
| `shoulderL / shoulderR` | torso | shoulders | 有 |
| `capeG` | torso | cloak | 有（但读错了物品） |
| `torsoG` | torso | chest / belt / amulet | **新增** |
| `skirtG` | skirt | chest 的下摆 | **新增**（沿用现有 skirt 的摆动曲线） |
| `armL / armR`（袖口段） | armL / armR | gloves | **新增** |
| `kneeL / kneeR`（靴筒段） | kneeL / kneeR | boots | **新增** |
| `handL / handR` | elbowL / elbowR | ring | **新增** |
| `relicG` | torso（腰侧） | relic | **新增** |
| `fateG` | foot（脚下） | fate | **新增** |

> 靴子必须挂 `knee`（小腿），不能挂 `leg`：`leg` 是髋关节，走路时会把人腿拉成橡皮。
> 这是一个改完才能发现的坑，先写在这里。

### 5.2 拼装 → 合并 → 一次绘制

```
模组键 (slot, family, lod) → 零件表 parts[] → 逐件建 geometry + 应用矩阵 + 烘顶点色
   → 按「挂点」分组 → 合并成 1 个 BufferGeometry → 1 个 Mesh（共用 1 份主材质）
```

- **为什么必须合并**：33 族 × 平均 8 件 ≈ 78 个小 mesh。玩家只有一个纸娃娃，但 78 个 mesh
  配 78 次「材质设置 + 绘制」在手机上依然浪费；合并后是 **≤ 11 个**（一个挂点一个）。
- **没有 `BufferGeometryUtils`**（`lib/three.min.js` 里没有 `mergeBufferGeometries`）→
  自己写 `mergeGeos()`，约 50 行：`toNonIndexed()` → 逐属性 concat → 生成 position/normal/color。**不许引第三方**。
- **颜色烘进顶点色**：一份 `MeshStandardMaterial({ vertexColors: true, flatShading: true })` 通吃所有部件，
  4 个材质通道（主面/暗部/金饰/纹样）退化成顶点色。这样 11 个挂点共用 1 份材质 → 状态切换只有 1 次。
- **品质光单独一件**：`emissive` 是材质级的，顶点色做不了 → 稀有度 ≥ 玄品（`magic`）时，
  多建 **1 件**发光小件（该件品质色的独立材质），最多同时 4 件。

### 5.3 LOD：8 档 → 3 段

| 段 | `baseVar` 阶 | 内容 |
|---|---|---|
| 简 | 0~2 | 只有「轮廓件」，无纹饰、无扣饰（每族 3~4 件） |
| 中 | 3~5 | + 层叠件 / 边缘 / 一件扣饰（6~8 件） |
| 繁 | 6~7 | + 纹样片 / 流苏 / 第二层甲片（9~12 件） |

> 只在**同一套件**上加件、不换件 —— 保证「同一族越升阶越繁复」的连续感，
> 玩家升阶时看到的是「长出来了」，不是「换了一件新东西」。

### 5.4 缓存与回收

- `_dollGeoCache[key]`，`key = slot|family|lod|rarity|cls`；命中直接 `clone()`。
- 换装时 `clearGroup` 必须**先 dispose geometry、再从 `a.mats` 摘掉本次新建的材质**
  —— 注意共享材质（主材质、身体材质）**不能 dispose**，否则下一件装备直接黑。
- 判断依据用引用白名单，不用「是不是新建的」：`Doll.sharedMats` 里的永远跳过。

## 6. 数据契约

新文件 `src/data/data-doll.js`（纯数据 + 纯函数，不碰 THREE，与 `data-vfx.js` 同构）：

```js
const DOLL_PARTS = {
  helm: {
    A: {                       // 巾帻族
      anchor: 'helmG',
      mats: { main: 'cloth', sub: 'dark', trim: 'gold' },
      parts: [
        // g 原语 / s 尺寸 / p 位置 / r 旋转 / m 材质通道 / c 颜色偏移
        { id: 'band',  g: 'cyl',  s: [0.148, 0.150, 0.070, 10], p: [0, 0.02, 0], m: 'main' },
        { id: 'tail',  g: 'box',  s: [0.030, 0.300, 0.012],     p: [0.05, -0.16, -0.13], r: [0.18, 0, 0.06], m: 'sub' },
        { id: 'gem',   g: 'box',  s: [0.034, 0.034, 0.016],     p: [0, 0.06, 0.142], m: 'trim' }
      ],
      lod: [
        { at: 3, add: [{ id: 'seam', g: 'box', s: [0.150, 0.012, 0.010], p: [0, 0.055, 0.130], m: 'trim' }] },
        { at: 6, add: [{ id: 'pin',  g: 'cyl', s: [0.010, 0.010, 0.270, 6], p: [0, 0.075, 0], r: [0, 0, Math.PI / 2], m: 'trim' }] }
      ],
      cf: { mage: { mats: { main: 'silk' } } }     // 职业只改材质与纹样，不改轮廓
    },
    B: { /* 兽面甲 */ }, C: { /* 立冠 */ }
  },
  /* chest / shoulders / cloak / gloves / boots / belt / amulet / relic / ring / fate … */
};

/* 唯一派生入口：物品 → 模组键。任何地方都不许自己拼 key。 */
function dollKeyOf(item)      // → { slot, fam, lod, sig }
function dollFamily(slot, v)  // 越界兜底 → 'A'
function dollLod(tier)        // 0~2 / 3~5 / 6~7 → 0/1/2
```

**四条硬规矩**

1. **`dollKeyOf` 是唯一出口。** 渲染、图标、说明页、测试全部走它 —— 这是「说明页按数据表实时生成」
   那条规矩在装备侧的等价物；各写一份必然走形。
2. **老档兜底**：`baseVar` 可能不存在（早期存档）。优先按 `baseName` 反查 `ARMOR_BASES` 定位变体下标；
   查不到再退 `fam = 'A'`。**必须可枚举验证：384/384 件基底都能解析出族**（测试里穷举）。
3. **按阶/按变体取数组一律兜底**（`list[tier] || list[list.length-1]`）。
   这条是拿线上白屏换的：`BASE_TIERS` 5→8 时 `itemVisualColor` 漏改，`palette[0]` 直接崩。
4. **命名先查重**：`DOLL_` 前缀（已确认 `src/` 内未占用）。新表名、新机制名都要先全局 grep ——
   和「跨系统取名」是同一条规矩，历史上已经因为同名覆盖踩过一次。

## 7. 材质与品质

### 7.1 4 个通道 → 顶点色

| 通道 | 谁用 | 颜色来源 |
|---|---|---|
| `main` | 板 / 布 / 皮的主面 | 阶材质（`METAL_PALETTE`，本作实际取前 8 阶）× 职业基色 |
| `sub` | 内衬、绑带、暗部 | 阶材质暗色 × 0.7 |
| `trim` | 金饰、边沿、扣 | 阶金属色 + 职业 `trim` |
| `accent` | 纹样片、稀有度小件 | 品质色（发光件单独材质） |

### 7.2 品质怎么看得见（**不再整件染色**）

现在的做法是把品质色按 42% 混进主色（`itemVisualColor` 里 `base = mixHex(base, glow, 0.42)`），
结果 8 阶材质的差别被品质色吃掉 —— 玄铁和太初在白装下是同一个颜色。

新口径：

| 品质 | 表现 |
|---|---|
| 凡品 | 无附加件 |
| 灵品 | + 1 处 accent 小件（暗光） |
| 玄品 | + 2 处 accent + 边沿金线 |
| 神品 / 套装 / 传世 | + 3 处 accent + 1 件**签名件**（该件独有，见 §7.3） |

**主色只由「阶 + 职业」决定，品质只加「件」和「光」。** 这样「重不重」和「贵不贵」是两个独立读得出来的信息。

### 7.3 传世签名件

40 件传世各给一件 3~5 个原语的签名件（`DOLL_SIG[uniqueId]`），挂在它自己的槽位上。
18 套套装不逐件做，只做「套装饰带」：颜色 + 一件同款挂饰（`SETS[id].color` 已有）。

> 40 × 4 件 ≈ 160 条数据 ≈ 250 行。这是整个方案里最像「素材设计」的一块，也是最值钱的：
> 玩家认装备靠的就是这 40 个剪影。

### 7.4 纹样（可选，P4）

一张 512×512 程序化图集，6 格纹样（云纹 / 雷纹 / 鳞 / 符 / 藤 / 骨），
按「阶 + 族」选格，贴到 `trim` 片上。**代价**：贴图会打破「11 个挂点 1 份材质」的合并，
必须单独成 mesh → 预算从 11 涨到 14。所以放在 P4，且**只有在窗口分辨率下真的看得出才做**
（512 屏幕上 2 厘米的纹样 = 看不见，那就别做）。

## 9. 性能预算

| 项 | 预算 | 依据 |
|---|---|---|
| 装备绘制（主通道） | **≤ 11**（一挂点一 draw），+ accent ≤ 4 | 实测 14 格全装 +30 draw（含武器 8） |
| 装备绘制（阴影通道） | 同量级 | 阴影是开的（`game.js:279`），合并同样省一半 |
| 材质实例 | **≤ 5**（主材质 1 + 品质光 ≤ 4） | 共用一份，白闪才能整体一致 |
| 顶点增量 | **≤ 7600**（实测 6765） | 裸身 57 mesh / 59 draw；全装 87 mesh / 89 draw。原写 3500 是拍脑袋的估计，实测翻倍 —— 成对槽位镜像后本来就要两份 |
| 单次换装耗时 | ≤ 8 ms（真机） | 有缓存时 ≈ 0 |
| 换装 50 次显存 | geometries/textures **不增长**（±2） | `renderer.info.memory` 断言 |

> 只有玩家一个纸娃娃（`applyPaperDoll` 全仓只有 `game.js:1716` 一处调用，NPC 不穿装备），
> 所以这里的瓶颈不是绘制，是**换装重入**和**顶点数**。别按「同屏 20 个纸娃娃」做预算，会过度设计。

## 13. 风险与反例

| 风险 | 表现 | 对策 |
|---|---|---|
| **剪影好看，动起来崩** | 战甲的硬裙甲在屈膝时插进大腿 | 裙甲挂 `skirt`（现有摆动组），不用硬片；单件长度 ≤ 0.42（现有裙长） |
| **比例漂移** | 连着三个版本各加 2 厘米，最后角色像个桶 | 铁律：总高变化 ≤ 2%、总宽 ≤ 8%，测试里断言包围盒 |
| **白闪漏注册** | 挨打只有身体闪，装备不闪 → 像贴纸 | 断言「装备 mesh 材质 ∈ a.mats」 |
| **共享材质被 dispose** | 下一件装备全黑 | `Doll.sharedMats` 白名单，永不 dispose |
| **老档 `baseVar` 缺失** | 老角色一身白装、看不出穿了什么 | `baseName` 反查 + 穷举测试 |
| **族名与既有系统撞键** | 数值悄悄被覆盖（历史上发生过） | 全局 grep；`DOLL_` 前缀已确认空闲 |
| **过度设计** | 给 NPC 也穿、给每个小怪也穿 | 明确不做：只有玩家一个纸娃娃 |

## 14. 明确不做

- 不做骨骼动画 / 蒙皮（现有是关节 Group 手工摆，装备跟关节走就够）
- **不改造 `skel.js` 的骨骼版纸娃娃**（`applySkelDoll` 全仓零调用，是 GLB 路线的遗留；本方案只在
  `charforge` 这条路径落地。将来真走 GLB 再另立计划，否则两边一起改必然只改一边）
- 不做布料模拟（披风/裙摆继续用现在的正弦摆动）
- 不给 NPC 和小怪穿装备（`applyPaperDoll` 只服务玩家）
- 不改角色基础比例、不改判定半径
- 不引第三方库（没有 `BufferGeometryUtils` 就自己写 50 行）
- 不做「装备外观影响移速/攻速」这类联动（数值系统的事，别串到渲染层）
