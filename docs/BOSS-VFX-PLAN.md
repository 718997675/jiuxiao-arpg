# Boss / 怪物技能特效升级计划 · 从「一个圈」到与角色同档

> 状态：**待拍板 · 未动一行代码**
> 提出：2026-10-28 ｜ 分支：`feat/skill-refactor`
> 关系：`docs/SKILL-VFX-PLAN.md` 的**镜像方案**。那份管玩家 15 技能，这份管怪物端 36 种形态。
> 不改任何数值与判定口径（唯一例外是 §4.1 提出的「前摇」——那是公平性问题，必须动）。

---

## 0. 一句话

怪物这边不是"做得糙"，是**整个表现层只有贴地的东西**：

> **13 种 Boss 技能里，11 种的主视觉是一个躺在 `y=0.06` 的圆。**

根因不在每个技能写得敷衍，而在 `FX.telegraph()` 这个原语**只接受半径、只画圆**。
于是「直线冲撞」「锥形火线」「落下石头」全都被迫用圆去近似。
要跟角色同档，顺序必须是：**先补原语（能立起来、能是别的形状），再按判定形状重排**。

## 1. 现状体检（全部是代码事实）

### 1.1 表现层只有 10 个原语，其中 6 个是"贴在地上的"

`src/fx.js` 全文只导出这些（行号为函数定义处）：

| 原语 | 出处 | 形状 | 有高度吗 |
|---|---|---|---|

| `FX.spark` / `FX.blood` | `fx.js:404/406` | 同上，固定参数 | 有 |
| `FX.ring` 扩张环 | `fx.js:408` | `RingGeometry` **躺平 y=0.08** | ✗ |
| `FX.flashCircle` 地片 | `fx.js:419` | `CircleGeometry` **躺平 y=0.07** | ✗ |
| `FX.telegraph` 预警 | `fx.js:431` | `CircleGeometry` + 细边环，**只有半径参数** | ✗ |

| `FX.beam` 光束 | `fx.js:462` | `THREE.Line` 8 段抖动（`linewidth` 在 WebGL 无效 → 恒 1px） | 有（但看不见） |

| `FX.text` 飘字 | `fx.js:~530` | DOM | — |

**没有**：立起来的柱 / 剑影 / 盾 / 石 / 藤蔓、贴花残留（焦痕裂纹）、地纹、非圆形的预警、有宽度的光束。

对照`docs/vfx-playground.html`（玩家侧特效台）已经有而游戏里**还没有**的：
`field`（地纹）、`spinBlades`（绕身剑影）、`spinShields`（盾阵）、`shock`（冲击波）、
`decal`（裂纹）、`geyser`（喷柱）、`arc`（弧刃）、`spr`（贴图粒子）、`guardRing`。
**这就是"角色效果"和"怪物效果"的全部差距来源** —— 不是谁用心，是有没有原语。

### 1.4 三个硬伤（按严重程度排）

**① 3 个技能零前摇 → 躲不掉（这是公平性问题，不只是观感）**

| 技能 | 判定 | 倍数 | 前摇 |
|---|---|---|---|
| `quake` | 圆 R8.5 | ×1.6 | **0 秒**，当帧结算 |
| `frostnova` | 圆 R7（+减速 2.5s） | ×1.1 | **0 秒**，当帧结算 |
| `curse` | 距离 <14 | ×0.6（+减速 3s） | **0 秒**，当帧结算 |

`quake` 是 8.5 码瞬伤 ×1.6 —— 玩家站在范围里没有任何反应窗口，只能靠"预判它会放"。
这跟特效好不好看无关，是**读不出危险**。修法是加 0.8~1.1s 前摇（数值不变，只是延后结算）。

**② 形状 ≠ 判定**

- `fireline`：判定是 6 个圆串成的直线带，画面是 6 个圆一个个冒出来 → 看不出这是"一条火线"
- `charge`：判定是沿路径的矩形，画面预警是**刷在自己脚下**的一个圆 → 玩家不知道它要冲向哪
- `curse`：判定其实是"距离 <14 就必中"，画面却画一条从 Boss 到玩家的线 → 看起来像可以躲的弹道

**③ 主视觉 11/13 是贴地圆**

相机是 46° 高俯角（见 `SKILL-VFX-PLAN.md` §1.5），**躺在地上的薄片最不占屏幕面积**。
在这个视角下，竖直方向的东西才显眼 —— 而怪物端一根竖柱、一块立石、一把剑影都没有。

## 2. 验收（先定标准，再谈做法）

| 指标 | 定义 | 测法 |
|---|---|---|
| **可读性** | 任取一个 Boss 技能的高光帧，**遮住 UI 和颜色**，能说出"这是砸/是冲/是火线/是落石" | `dev/boss-vfx-shot.js` 逐技能出图 + 灰度版 |
| **公平性** | 所有造成 >1.0× 伤害的 Boss 技能，**前摇 ≥ 0.7s 且有形状匹配的预警** | 静态扫描 `bossPattern` 的 `telegraph` 覆盖率 |
| **性能** | 单个 Boss 技能 ≤ 6 draw call；`chaos` 六招连放峰值 ≤ 基线 +30% | `Game.renderer.info.render.calls` |
| **同档** | 每个 Boss 技能至少含 1 个**非贴地**元素（柱/实体/剑影/贴花） | 逐条核对 §4 表 |

> 最后一条是关键口径：**"非贴地"是硬门槛**。只要还是躺着的，就还是"一个圈"。

## 3. 架构：判定形状决定预警形状（一对一，不许近似）

这是本方案唯一不能妥协的结构性决定。现在之所以全是圆，是因为**没有别的形状可选**。

| 判定形状 | 用什么预警 | 用在 |
|---|---|---|
| 圆点 | 圆 + 内圈收缩 + 地面裂纹 | `slam` `rocks` `meteor` `swordrain` `roots` |
| 直线带 | **矩形带**（宽度 = 判定宽度）+ 箭头 | `charge` `fireline` |
| 环形 | **空心环**（内径/外径 = 判定） | `poisonnova` `quake` `frostnova` |
| 扇形 | 扇面 + 边线 | 新增（见 §4.2 建议给酋长） |
| 锁定（必中） | **标记挂在玩家脚下**，不是连线 | `curse` |

**推论**：`FX.telegraph` 必须扩成 `FX.zone({shape, ...})`，`shape ∈ circle|rect|ring|sector`。
这一个改动就同时解掉 §1.4 的 ② 和 ③。

## 4. 逐条方案

### 4.1 P0 · 公平性（3 个零前摇 + 1 个无方向）

| 技能 | 改法 | 判定 |
|---|---|---|
| `quake` | 0.9s 前摇：地面**同心环从外向内收**（读作"压迫感"），收到中心才炸；炸时加 `shock` 竖波 + 地裂纹 | 不变 |
| `frostnova` | 0.8s 前摇：**空心环**由内向外扩到判定半径（读作"寒气推出去"），到边才结算；加地面结霜贴花 | 不变 |
| `curse` | 0.7s 前摇：**锁定标记直接挂在玩家脚下**（不是连线），标记填满才生效；加"魂丝"从 Boss 连到标记 | 不变 |
| `charge` | 蓄力时画**矩形带**从 Boss 指向玩家（长度 = 冲刺距离，宽度 = 判定宽）；冲锋中留**残影**（3 段渐隐的自身虚影） | 建议同步从圆形改矩形（§6-④） |

> 这四条不改伤害、不改倍率，只把"结算时机"推后并补上形状。改动集中在 `bossPattern()` 的 4 个 case。

### 4.2 P1 · Boss 技能本体（让 11 个圆长出手脚）

| 技能 | 现在 | 目标（新增的非贴地元素用 **粗体**） | 要补的原语 |
|---|---|---|---|
| `slam` | 地圈 → 闪片 | 抬臂前摇 → **巨影落下**（复用 `TEX.blade` 或拳影）→ 落地**弧形冲击波** + **裂纹贴花** + 碎石 | `wave` `decal` |
| `roots` | 3 个绿圈 | 圈内先裂土 → **藤蔓/尖刺从地里长出**（锥体 + 藤状弯曲）→ 缠绕 0.5s 后缩回 | `spike` |
| `rocks` | 灰圈 + 灰粒子 | 圈内出现落点 → **石头实体从天上掉**（旋转的多面体）→ 落地碎成 3 块残留 | `boulder` |
| `meteor` | 4 个红圈 | 同上，但**带火焰拖尾的陨石** + 落地**火柱** + 焦痕 | `boulder` `column` `decal` |
| `swordrain` | 10 个金圈 | **剑影从天而降**（`TEX.blade` 现成，玩家侧已做好，剑尖朝下）→ 每把插地留 1.5s | `blade` |
| `fireline` | 一串橙圈 | 矩形带预警 → **6 根火柱依次拔起**（竖直锥 + 上升余烬）→ 地面留**焦痕** | `rect` `column` `decal` |
| `poisonnova` | 3 层同心圆 | 改成**空心环向外推**（内径从 0 长到判定），环上冒毒泡 → 边界外留**毒斑** | `ringZone` `decal` |
| `quake` | 环 + 片 | 见 P0；补**地裂**（从中心放射的 6 条裂纹贴花） | `decal` |
| `frostnova` | 环 + 片 | 见 P0；补**地面结霜**（六角雪花贴花）+ 冰棱残留 | `decal` `spike` |
| `curse` | 1px 线 | 见 P0；补**魂丝**（有宽度的束缚带）+ 玩家身上紫色缠绕 | `ribbon` |
| `summon` | 紫圈 + 小圈 | **裂地冲出**（每只脚下先裂、再钻出来）+ 紫色**传送门柱**（竖直椭圆） | `spike` `column` |
| `ringshot` | 12 个光球 | 球加**拖尾** + 元素外观（火/冰/毒各不同）+ 起手时**环状蓄能** | `trail` |

### 4.3 P1 · 生命周期

| 事件 | 目标 |
|---|---|
| **Boss 出场** | 场地**地纹先亮**（`field`，Boss 家族色）→ **竖直光柱**从祭坛升起 → Boss 在柱中显形 → 柱散成粒子。配 boss BGM 起手。这是"这一战要开始了"的唯一信号，现在完全缺失 |
| **狂怒** | 保留环，加**竖直气浪上涌** + 地面**蛛网裂纹** + 屏幕边缘暗红 0.4s（phase 1/2 各一次，形态递进） |
| **Boss 死亡** | 0.4s 慢动作（`hitstop`）→ **碎片爆散** → 地面**焦痕/残骸**留 3s → 掉落**光柱**（现在掉落只是地上一个物件） |

### 4.4 P2 · 小怪与词缀（量大但单点便宜）

| 对象 | 目标 | 优先级理由 |
|---|---|---|
| 近战普攻（40 只怪的主力） | 抬手时**弧光**（半透明扇面，用 `FX.slash` 但立起来）+ 命中**火花** | 现在零特效，玩家挨打不知道被谁打的 |
| `healer` | **治疗光束**从施法者连到目标（0.5s，绿色，有宽度）+ 目标身上**上升光尘** | 现在看不出它在治谁，"先杀奶"这条打法读不出来 |
| `bomber` | 真正的**引信**（头顶/身上闪烁的橙光球，频率随倒计时加快），不再借受击闪白 | 唯一有预警的怪技能，值得做对 |
| `coward` | 逃跑时**残影 + 尘土** | 现在只有一个 `+` 飘字 |
| `frost` `venom` `vampiric` `swift` `thorns` `warded` `split` | 各给一个**挂在怪身上的常驻微标识**（不是每次触发的爆发）：冰晶护体 / 绿雾 / 血色雾 / 残影 / 荆棘环 / 元素色罩 / 分裂时裂开 | 12 条词缀里 7 条零视觉，靠猜 |

> P2 的原则：**常驻微标识 > 每次触发的爆发**。40 只怪同屏时，每次触发都炸一朵花会变成视觉噪音，
> 常驻一个小标识反而能让人一眼看出"这只怪有什么词缀"。

## 7. 附：这份清单是怎么得出的

全部结论来自静态读代码，没有一条是"感觉"：

```bash
# 表现点总数
grep -n "case '" src/game.js | sed -n '/bossPattern/,+200p'   # 13 个
# 原语清单
sed -n '340,540p' src/fx.js
# 各文件用了哪些原语
grep -o "FX\.\w*" src/game.js | sort | uniq -c | sort -rn
```

实测分布（`src/game.js` 共 **170 次可见** FX 调用，已排除 `text` 与生命周期类）：

```
ring 48 (28.2%) · burst 40 (23.5%) · flashCircle 33 (19.4%) · beam 15 (8.8%)
area 10 (5.9%) · telegraph 8 (4.7%) · projectile 7 (4.1%) · spark 5
slash 2 · blood 2
```

`ring + flashCircle + area + telegraph` = **99 次，占 58.2%** —— 这就是"一个圈"的量化形态。
再加 `slash`（也是躺平扇面）到 **101 次 / 59.4%**：**每三次表现里就有近两次是贴地的一片。**
