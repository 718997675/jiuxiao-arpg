九霄·山海录 — 性能优化方案

v1.0.6 ｜ 瓶颈定位、已完成的改动、以及「继续优化网页 / 做 EXE / 换引擎」三条路怎么选
一句话结论：现在卡的原因是 draw call 太多，不是浏览器不行。换 Electron 做 EXE 一个 draw call 都不会少， 换引擎要重写整个项目。所以先走「继续压网页版」这条路——本轮已经压掉一半，还剩两处可以再压一半左右。

1. 瓶颈在哪：用数据说话

先说清楚一件事：卡顿有两种，一种是「算得慢」（JS 逻辑、物理、AI），一种是「画得慢」（渲染）。这个项目是后者。

1~7 ms每帧逻辑耗时（update）
20~120 ms每帧渲染耗时（render）
22单只怪的网格数量
2133最坏情况每帧 draw call

逻辑几乎不花钱，渲染是 10~20 倍的差距。而渲染里最贵的不是「像素多」，是 draw call 数量—— 每一个网格、每一盏灯的每一个投影体，都要 CPU 单独提交一次绘制指令。这个项目的 draw call 构成是这样的：

来源数量说明
场景本体（地形 / 建筑 / 植被）约 170固定成本，不随战斗变化
场景本体的阴影约 307固定成本
每只普通怪（主画面）22头 / 发 / 眼×2 / 躯干 / 衣襟 / 腰 / 扣 / 领口 / 腿×2 / 靴×2 / 臂×2 / 手×2 / 武器 2~4
每只普通怪（阴影通道）22和主画面一样多——这是之前没注意到的大头
每颗粒子（旧实现）1一次技能爆发几十上百颗

所以 36 只怪挤在一起时：170 + 307 + 36×22 + 36×22 ≈ 2133。其中 1584 个是怪物贡献的， 而怪物投不投影（1584 里的 792）比怪物画不画还贵。

3. 三条路怎么选

路线能解决什么解决不了什么成本建议
A. 继续优化网页版 draw call 数量本身 低端集显的填充率上限 低，不动交付形态 先做这个
B. Electron 打 EXE 浏览器标签页节流、WebGL 上下文丢失、用户浏览器差异、能指定 GPU 后端 draw call 一个不少——里面跑的仍是同一个 Chromium + 同一个 WebGL 安装包 150MB+、每次更新要重新分发、失去「发链接就能玩」 等 A 做完再考虑
C. 换技术栈 Unity 的 SRP Batcher / GPU Instancing 能自动合批；WebGPU 能做 indirect draw —— 8,200 行 JS 全部重写，纸娃娃 / 存档 / UI / 技能全重做，等于重开项目 除非要商业化发行

B. Electron 做 EXE — 不是渲染优化

这个方向常被误解。Electron 的本质是「把 Chromium 打包进安装包」，所以：

  • 不会减少 任何一个 draw call。2133 还是 2133。
  • 会改善 标签页在后台被降频、切走再切回来卡一下、部分浏览器默认不开硬件加速、WebGL 上下文丢失后不恢复。
  • 会改善 可以强制指定 --use-angle=d3d11 之类的后端，绕开驱动兼容问题。

换句话说：它是「交付方式」的升级，不是「性能」的升级。 如果目标只是「不卡」，做了 EXE 还是会卡； 如果目标是「能离线玩 / 能发安装包 / 不受用户浏览器影响」，那它有价值。

成本：安装包 150MB 起（Chromium 本体）、要处理自动更新、Mac/Windows 分别签名、失去「发个链接就能玩」这个最大优势。 建议 A 做完之后，如果仍然需要桌面发行再做，并且保留网页版。

C. 换技术栈 — 现在不划算

  • PixiJS：2D 渲染库，这个项目是 3D，不合适。
  • WebGPU 自研：确实能把 draw call 压到个位数（indirect draw + 实例化），但要重写整个渲染层，而且老设备 / Safari 支持还不完整。
  • Unity / Godot：真正的优势是引擎自带 SRP Batcher、GPU Instancing、LOD、遮挡剔除，不用自己写。 代价是 8,200 行 JS 全部作废——纸娃娃系统、存档、装备词缀、符文之语、Boss AI 都要重做，约等于重开一个项目。

判断标准很简单：如果这个项目要变成「要卖的产品」或者需要同屏几百个单位，才值得换； 如果是一个自己玩 / 小范围分享的作品，A 路线的性价比高一个数量级。

5. 需要你确认的两件事

① 你现在是在什么设备上觉得卡？ 这个信息很关键。如果是一台只有集显的笔记本、浏览器缩放 150%、屏幕 2K/4K， 那瓶颈可能是「填充率」而不是 draw call——那种情况下 A 路线收益有限，正确的做法是降分辨率 / 关抗锯齿， 而 B（Electron）和 C（换引擎）都救不了。

看的方法：游戏里按 F12 打开控制台，输入 Game.perf.fps 和 Game.perf.level， 把数值告诉我。如果 level 已经自己降到 2，说明自适应已经把 dpr 压到 1.0 并关了阴影还是不够， 那就是硬瓶颈，需要走 A-3。

② 这个项目最终要交付成什么？ 「发个链接就能玩」还是「要一个能下载的安装包」？ 这直接决定 B 要不要做。
