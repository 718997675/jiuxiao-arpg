# 任务台账（docs/status/）

> 换电脑、换账号、隔了几天再回来 —— 打开这一个目录就能接上，不用翻聊天记录。

## 为什么放在这里

`.workbuddy-ai/memory/` 里也有日志，但它在 `.git/info/exclude` 里，**不进 git**
（仓库是公开的 Pages 站点，日志不能公开）。所以换机器 / 换账号后那些日志**不会跟过来**。

跨机器必须活下来的东西，只能放仓库里 —— 就是这里。

> ⚠ 代价：这个目录会随仓库公开。只写「做到哪、下一步做什么」，别写密钥、内网地址、私人信息。

## 一条分支一份，别合并成一份

```
docs/status/main.md               ← main 的台账
docs/status/act-expansion.md      ← feat/act-expansion 的台账
docs/status/skill-refactor.md     ← feat/skill-refactor 的台账
```

**为什么不写成一个总文件**：三条线各自改同一个文件，合并时必然冲突，
而且冲突恰好落在「进度」这种最不该手工合并的内容上。一分支一份，天然零冲突。

**那怎么看全局**：`./dev/status.sh` —— 它会直接从各分支的 git 对象里读，不用切分支。

## 格式约定（脚本会解析，别改结构）

| 元素 | 写法 | 说明 |
|---|---|---|
| 进度行 | `> 当前：M2 任务系统（进行中）` | `status.sh` 摘要显示这一行 |
| 节点表 | `\| M1 \| 卷/营地/传送 \| ✅ \| … \|` | 统计 `✅` 数与 `\| M数字` 行数算进度 |
| 状态符号 | `✅` 完成 · `🔄` 进行中 · `⬜` 未开始 · `⏸` 暂停 · `❌` 取消 | 只认这五个 |

**必填的四段**（缺了就等于没交接）：

1. **一句话现状** —— 现在到哪了
2. **节点表** —— 大计划的每个节点 + 状态 + 产物 + 对应提交
3. **下一步** —— 具体到「打开哪个文件、改什么」，不是「继续做任务」
4. **卡点** —— 等谁拍板、卡在什么问题上

## 什么时候更新

**每次任务收尾都更新**，和写日志同等重要。判断标准：
- 干完了某个节点 → 状态改 `✅`，补上提交号
- 干到一半 → 状态改 `🔄`，在「下一步」里写清楚断在哪一行
- 有了新决定 → 写进「决策记录」，带日期和理由

**别攒着**。攒到最后写，一定会漏掉「当时为什么这么选」。

## 换账号后怎么接上

```bash
git clone https://github.com/718997675/jiuxiao-arpg.git && cd jiuxiao-arpg
./dev/status.sh            # 三条线各自到哪了，一眼看完
./dev/branch.sh act        # 切到要接着做的那条
cat docs/status/act-expansion.md   # 细看这条线的节点表、下一步、卡点
```

然后就能直接开工，不需要任何人回忆「上次做到哪」。
