## 机制说明页（菜单第 10 页 · v1.8.2）

用户反馈「机制已经很复杂了，希望菜单里有说明，并且以后更新功能要同步更新说明」。

### 做法：内容按数据表实时生成
`ui.js` 新增 `renderHelp()`，**所有条数和名字都从数据层读**，不写死：

| 说明里的数字 | 读自 |
|---|---|
| 14 个槽位 | `SLOT_ORDER.length` + `SLOT_NAME` |
| 8 阶基底（凡兵→太初） | `BASE_TIER_NAME` |
| 83 条词缀 + 一二三阶分布 | `AFFIXES` 遍历 `tier` |
| 12 套套装（通用/职业） | `SETS[id].cls === null` |
| 36 个技能 / 108 变体 / 36 条机制 | `SKILLS` + `specialVariantCount()` |
| 17 种机制名 | `SKILL_SPECIALS` |
| 128 个天赋节点 / 8 枚协同星位 | `TALENT_NODES` + `TALENTS.synergy[0].nodes` |
| 12 条精英词缀 / 怪物数 | `ELITE_AFFIXES` / `MONSTERS` |
| 符文之语条数 | `RUNE_WORDS` |
| 技能条格数 / 等级步进 | `SKILL_BAR_SLOTS` / `SKILL_LV_STEP` / `SKILL_LV_MAX` |
| 难度描述 | `DIFFS` |

以后加装备 / 加技能 / 调数值，说明页自动跟上，不会出现「说明写 64 条、实际 80 条」。

### 布局（用户指定）
左边竖排 10 个分节页签，右边只渲染当前这一节 —— 跟主菜单同一个交互习惯。
- `#helpPanel` 内是 `.hp-wrap`（flex）→ `.hp-nav`（124px 竖排）+ `.hp-body`（滚动）
- 手机端 `body.touch` 下 nav 改成顶部横向可滑
- **短名自动反解**：每节标题是 `'一 · 怎么玩'`，末尾用正则 `^[一二三四五六七八九十]+\s*·\s*` 去掉序号当页签名 —— 新增一节只写一次 `sec(...)`，不用再维护页签名列表
- 页签名控制在 8 字内（124px 放得下），所以「套装 · 符文之语 · 传世」改叫「套装与符文」，传世挪到 note 和正文

### 接入

- 快捷键 `H` / `?` 打开（ui.js 的 keydown 分支）

## v1.8.3 收尾：传世体系 + 说明页重做 + Shift 换栏

接手另一账号额度中断的半成品（工作区已改完但未提交）。本轮补完并修复三处反馈：

### 1. 行间裸逗号（用户截图指出，独占一行）
根因不是文案，是 `renderHelp()` 里的 `sec(title, note, body)`：body 传的是**数组**，
直接 `${body}` 会走 `Array.toString` 变成「行,行,行」，那个逗号在 `.hp-sec` 里单独成行。
改成 `body.join('')`（数组 / 字符串两种入参都吃）。`dev/probe-help.js` 加断言：
每节 `innerText` 里不允许出现只含 `,，、` 的行。

### 2. 品质说明（用户追问「现在八阶装备，为什么品质只列凡品/灵品/玄品/神兵」）
原来把 6 个 `RARITY` 平铺成一行，套装 / 传世看着像升品链的第 5、6 档。改法：
第四节先写「三条线」（基底阶 / 品质 / 类型），品质只列升品链 4 档（带词条数），
套装、传世各自单开一行（绿色 5 词条 / 红色 20 件）并指路第六节。
代码事实：`game.js` 升级品质链 `common→magic→rare→legendary`，unique / set 明确拒绝；
品质与基底阶完全正交（同一基底可以凡品也可以玄品），说明里补了一句例子。
**遗留**：品质「神兵」与八阶「仙品 / 神兵」撞名，已写进 MEMORY.md 等用户拍板改名。

### 3. Shift 换栏 + 换栏标识
- `SKILL_BAR_SET_KEY = 'shift'`，备用 `` ` `` / `V`，`e.code === 'Backquote'` 兜底输入法；
  菜单开着时不换栏（避免 Shift+左键出售 / 洗点顺手翻栏）。`dev/test-hotkeys.js` 23 项。
- 换栏角标 / 术法面板按钮改成剑 / 盾图标 + 「1/2」（`bar_atk` / `bar_def` 用实心剪影，
  细描边在 13–16px 会糊成一根线）；手机 HUD 补换栏小按钮（图标 + 套数角标）。
- 说明页「换栏」行原本把图标塞进句子中间，换行会把「输出栏 / 防守栏」拆到图标上下两行，
  改成两枚 `.hp-tag.kc` 小牌。

### 4. 传世提示框文案去重
9 件授予类的 desc 原来是「领悟秘技【X】——风味」，和提示框里的「名称（X）」重复，
改成只留风味句；提示框显示 `秘技 · 幽冥蚀骨（蚀骨毒雾） 九幽之下，血亦是毒。`

## v1.8.5：根基加点 + 穿戴需求（commit 9b8204d，tag v1.8.5）

用户原话：「添加基础属性加点系统，根据职业不同基础属性加点影响的人物属性不同……
装备也需要属性需求+等级需求……不满足的显示灰暗……PC 悬停 / 移动端点按看影响哪些进阶属性」。

实现要点（细节与后续待办见 `.workbuddy/memory/2026-10-25.md`）：
- `CLASSES[].weights`：每职业一张「根基 → 进阶」换算表，同名属性跨职业不同效；
  `deriveFromAttrs()` 统一换算，`computePlayerStats` 从「基础+成长+装备」改成四源合成。
- 加点：`ATTR_START_POINTS=5` + 每级 3 点，`attrTotalAt/attrSpentOf/attrLeft` 纯函数，
  `Game.attrState/allocAttr/resetAttrs/attrRespecFee` 落在存档 `attrAlloc`。
- 需求：`reqAttrOf(item, cls)` = 部位系数 × 品质系数 × **穿戴者职业**成长值；
  护甲只看体质（避免法系双重卡），传世额外要敏捷；`meetsReq` 静默判断给背包灰显。
- UI：道途面板顶部加点区（+1/+5/洗点），悬停与触屏点按共用 `attrTipHTML`。

踩坑：`Game` 对象字面量同名键后者覆盖前者 —— 天赋已有 `respecCost()`，
根基洗点改名 `attrRespecFee()` 才生效（否则显示天赋洗点的 1000 金）。
